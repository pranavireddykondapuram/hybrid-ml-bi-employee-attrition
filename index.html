Methodology. A logistic regression classifier was trained offline in Python (scikit-learn) on the cleaned dataset (52 exact-duplicate rows removed, 5,601 unique employee records), using an 80/20 stratified train/test split and balanced class weighting to correct for the ~35% / 65% attrition split. Numeric features were standardised; categorical features were one-hot encoded. The fitted weights below are embedded in this page and evaluated with a small JavaScript function — no server, Python runtime, or API call happens at prediction time.

Limitations. This is a moderate-signal, single-linear-model fit on synthetic-looking HR data with real data-quality issues (missing values, invalid ages, mixed casing) that were cleaned but not invented. Accuracy and AUC are reported exactly as computed — they are intentionally modest and should be read as directional signal for workforce planning, not as a hiring/firing decision tool for any real employee.

About this dashboard

This is a single self-contained HTML file — every chart, filter, table and prediction runs in your browser with no backend, database or Python process. It was built from an uploaded HR workforce spreadsheet of 5,653 employee records across 22 original columns, covering demographics, compensation, performance, engagement and employment status across 10 Indian cities and 10 departments.

Prediction problem

The dataset's Attrition field (whether an employee has left the company) was the natural target — it is the only outcome column, it had real business meaning, and a complementary Employment Status field let us recover values for the rows where Attrition itself was blank. The result is a binary classification problem: will this employee leave (Yes) or stay (No), addressed with a logistic regression model — see the Model Performance tab for exact, computed metrics.

    Uploading your own data

    The Upload dataset button reads an .xlsx/.csv file in-browser with SheetJS and tries to match its column headers (case-insensitively, with common synonyms — e.g. "emp id", "employee_id" and "ID" all map to the same field) to this dashboard's expected schema. Columns it can't confidently match are left blank rather than guessed. This works well for spreadsheets shaped like the original HR dataset; a very differently structured file may only partially populate the dashboard.
